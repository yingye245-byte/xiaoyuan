# 答辩要点与演示脚本

> 用途：答辩前 30 分钟过一遍本文件；演示时按「演示脚本」的 10 个步骤走，每步都能对应到评分点。

## 一、30 秒开场（讲清是什么、用什么做）

「我做的是校园二手闲置交易平台，服务本校学生买卖闲置。技术栈是 Spring Boot 2.7 + Thymeleaf 服务端渲染 + MyBatis-Plus + MySQL 8 + Redis + RabbitMQ + Spring Security，前后台页面全部由 Thymeleaf 片段复用渲染，没有用 Vue 之类的前端框架。除了课程要求的基础功能，我做了订单超时自动关闭、多级缓存、异步邮件三大高阶能力，并提供了 Linux + Nginx + systemd 的完整部署方案。」

## 四、高频追问与标准回答

**Q1：为什么用 Thymeleaf 不用 Vue？**
课程要求服务端渲染，且 Thymeleaf 与 Spring Security 集成后能直接在模板里做 `sec:authorize` 权限控制；前后台共用 `fragments/` 片段，减少重复代码。代价是交互不如 SPA 顺滑，但本项目以表单提交为主，完全够用。

**Q2：订单超时为什么不用定时任务扫表？**
扫表要全表扫描且时间不精确。用 RabbitMQ 延迟队列，下单即投递，到点由死信触发，精确且不占数据库；同时保留 `OrderTimeoutTask` 每 5 分钟兜底，防止队列消息丢失。

**Q3：怎么保证不超卖？**
物品状态从「在售(1)」到「交易中(5)」用 `UPDATE tb_item SET status=5 WHERE id=? AND status=1`，受影响行数为 0 说明被别人抢先，直接抛业务异常；下单前还有 Redis `SETNX` 锁兜底。

**Q4：幂等是怎么做的？**
进入下单页时服务端生成 UUID 放进表单隐藏域，同时不预占；提交时 `SETNX sc:idem:order:{token}` 过期 5 分钟，返回 false 说明重复提交，直接拒绝。刷新页面会拿到新 token 才允许再下单。

**Q5：缓存一致性怎么处理？**
写操作后主动 `delete` 相关 key（分类树、物品详情、热门、统计），读时 Cache-Aside；详情页对不存在 id 缓存空值 60 秒防穿透；缓存时间都较短（5~30 分钟），即使漏删也能自愈。

**Q6：怎么防止越权？**
三层：URL 级（Security 配置 `/admin/**` 需 ADMIN）、方法级（`@PreAuthorize`）、数据级（查订单/物品时校验 `sellerId/buyerId` 是否为当前用户，否则 403）。演示时可用 student03 访问 student01 的订单地址验证。

**Q7：密码怎么存的？**
BCrypt（强度 10）单向哈希，库里只有密文；登录由 Spring Security 的 `DaoAuthenticationProvider` 校验。SQL 里没有任何明文密码。

**Q8：图片上传怎么防攻击？**
白名单扩展名 + 单张 5MB/单次 25MB 限制 + UUID 重命名 + 只允许删除 `/upload/` 前缀路径；Nginx 直接 alias 静态目录，Java 不参与读图。

**Q9：邮件真发吗？**
默认 `mail.mock=true`：渲染模板后只写 `tb_mail_log`，不外发，答辩环境无外网也能演示；生产把 `MAIL_MOCK=false` 并配置 SMTP 即真实发送。

**Q10：项目怎么部署？**
见 `docs/03-部署文档.md`：JDK17 + MySQL8 + Redis + RabbitMQ + Nginx，jar 由 systemd 托管，Nginx 反代 8080 并直读 `/upload/`，密码全部走 `.env` 环境变量。

**Q11：担保交易的钱怎么保证不出错？**
四道闸门：一是金额只认服务端订单 `amount`，页面传什么都会被覆盖；二是流水与订单各自 CAS 更新，`rows=0` 时重新读取真实状态判定，不会出现「页面说成功但实际没扣」；三是收银台和支付提交都校验 `create_time + order-timeout-minutes`，页面倒计时只是提示，超时由服务端拒绝；四是加锁顺序统一为「订单 → 物品 → 流水」，并用 `uk_order` 保证一单一流水。

**Q12：买家一直不确认收货，卖家拿不到钱怎么办？**
`OrderTimeoutTask` 里除订单超时关单外，还有 `autoFinishPaid`：已支付超过 `app.order-autofinish-days`（默认 7 天）仍待交付的订单自动完成，并在同一事务里把支付流水 `1 → 4`、写 `settle_time`，托管款结算给卖家，避免资金永久挂账；后台「托管中的资金」按 `流水=1 且订单=1` 统计，结算后自动出账。
