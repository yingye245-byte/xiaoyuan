## 四、高阶能力（H1–H6）

### H1 订单全流程 + 幂等

状态机：

```
0 待支付 ──支付──> 1 已支付待交付 ──买家确认──> 2 已完成
   │                      └──卖家/买家取消──> 3 已取消（物品回到在售）
   └──30 分钟未支付（MQ 延迟消息 / 定时任务兜底）──> 3 已取消（reason=超时未支付）
```

- 物品状态联动：下单锁 `1 在售 → 5 交易中`，支付后 `→ 3 已售出`，取消后 `→ 1 在售`。
- CAS 更新：`update ... set status = 新 where id = ? and status = 旧`，影响行数为 0 即视为冲突并抛业务异常。
- 幂等：下单页生成 UUID 令牌，`SETNX sc:idem:order:{token}` 5 分钟；重复提交直接返回已有订单/提示重复。
- 订单号：`SC + yyyyMMddHHmmssSSS + 买家ID后四位 + 3 位随机数`。

#### H1-1 在线支付 + 担保交易（资金托管）

真实商户号（支付宝/微信开放平台）不可得，因此实现**模拟支付网关**，但订单与资金语义与真实平台一致：

```
下单 → /pay/{orderId} 收银台选渠道 → 模拟网关回调（HMAC-SHA256 验签）
     → 支付成功，款项进入平台托管（tb_payment.status=1）
     → 买家确认收货 → 订单完成，托管款结算给卖家
     → 超时未支付 / 取消订单 → 流水关闭（status=3），不产生任何扣款
```

- 支付流水表 `tb_payment`：`pay_no` 唯一、`order_id` 唯一（`uk_order`，一单一流水）、`channel`（支付宝/微信/校园一卡通）、`status`（0 待支付 / 1 支付成功托管中 / 2 支付失败 / 3 已关闭 / 4 已结算给卖家）、`trade_no` 网关交易号、`notify_time` 回调时间、`settle_time` 结算时间。
- 安全与防篡改：应付金额只取服务端订单金额（不信任页面传值）；回调签名 `payNo|orderNo|amount|tradeNo` 用 `app.payment.mock-secret` 做 HMAC-SHA256 校验；流水与订单各自 CAS 更新且失败后重读判定，重复回调/重复点击返回幂等结果而不是假成功；支付流水必须与路径上的订单一致，否则拒绝。
- 服务端兜底：收银台与支付提交都校验 `create_time + order-timeout-minutes`，页面倒计时不是唯一防线；加锁顺序统一为「订单 → 物品 → 流水」，避免 ABBA 死锁；订单状态变更通知在事务提交后（`afterCommit`）才投递 MQ，回滚不会发出错误通知。
- 资金语义：支付成功即 `tb_item` 置「已售出」，订单进入「已支付·待交付」；买家确认收货后订单完成，同一事务把流水 `1 → 4` 并写 `settle_time`，托管款结算给卖家；买家 7 天不确认收货时由定时任务（每天 03:30）自动完成并结算，避免资金永久挂账。
- 后台对账：`/admin/payments` 支持按流水号/订单号/物品名、状态、渠道筛选，展示「托管中的资金」（`流水=1 且订单=1`）与流水总数，并带订单状态列便于核对。

### H2 三级角色 + 菜单级 + 接口级权限


- 角色：`ROLE_USER`（注册默认）→ 发布物品后自动升级 `ROLE_SELLER` → `ROLE_ADMIN`（内置）。
- 菜单级：`tb_menu` + `tb_role_menu`，后台侧边栏按当前用户角色动态渲染。
- 接口级：`/admin/**` 要求 `hasRole('ADMIN')`；发布/编辑物品要求登录；审核、下架等动作另有 `@PreAuthorize` 权限码。
- 数据级：订单详情只对买卖双方或管理员可见；物品编辑/下架/删除校验 sellerId；留言删除校验作者或管理员。

### H3 RabbitMQ 三个场景

| 场景 | 队列/交换机 | 说明 |
| --- | --- | --- |
| 延迟取消订单 | `sc.order.delay.queue`（TTL=30 分钟，DLX=`sc.dlx`）→ `sc.order.cancel.queue` | 下单后发延迟消息，到期由 `OrderCancelConsumer` 走 CAS 取消并释放物品；定时任务兜底扫描 |
| 异步邮件 | `sc.mail.queue`（`sc.topic` / `sc.mail.send`） | 注册欢迎、审核结果、留言通知、订单状态变更，渲染模板后发送并记录日志 |
| 站内消息推送 | `sc.notify.queue`（`sc.notify.push`） | 审核结果、留言、订单状态变化写入 `tb_message`，前台右上角红点未读数 |

生产者统一在 `MqProducer`，异常只记录日志、不影响主业务；消费者在 `mq/` 包下三个 `@RabbitListener`。

### H4 多级缓存 + 购物车/浏览记录

- 浏览器/静态资源：Nginx 缓存（部署时）+ 本地 `echarts.min.js` 断网可用。
- 应用层：Redis 缓存分类、热门物品、物品详情（含空值缓存防穿透）。
- 浏览量：`INCR sc:item:views:{id}`，每累计 20 次批量回写数据库，避免每次详情页都写库。
- 购物车：`Hash sc:cart:{uid}`，field=物品 ID、value=加入时间，支持上限、清空、合计金额。
- 浏览记录：`ZSet sc:history:{uid}`，保留最近 20 条，详情页展示「最近浏览」。
- 分布式锁：`SETNX sc:lock:item:{id}` 防止并发下单同一物品。

### H5 Linux 部署

见 `docs/03-部署文档.md` 与 `deploy/`：JDK17 + MySQL8 + Redis + RabbitMQ + Nginx 反向代理 + systemd 托管 jar，日志与上传目录分离，生产 profile 全部走环境变量。

### H6 ECharts 看板

`/admin/dashboard` 四张图（近 7 天物品/订单趋势、分类分布、卖家成交额 Top、订单状态分布）+ 四个统计卡片（用户数、在售物品、累计成交、交易金额），数据来自 `/admin/api/stat/*`。

## 六、验收自查清单（答辩现场按顺序演示）

1. 首页 → 分类导航（带在售数量）→ 关键词 + 价格区间检索 → 分页。
2. 注册新账号 → 收到站内消息 + 邮件日志（`/admin/mail-logs`）。
3. student01 登录 → 发布物品（多图上传预览）→ 我的闲置显示「待审核」。
4. admin 登录 → 后台看板图表 → 物品审核通过 → 卖家收到站内消息/邮件。
5. student02 登录 → 物品详情 → 留言（卖家收到通知）→ 加入购物车 → 下单。
6. 重复点击下单 → 提示幂等拦截（订单不重复）。
7. 支付 → 物品变「已售出」→ 买家确认收货 → 订单「已完成」。
8. 另开一单不支付 → 演示超时关闭（现场可用 60 秒延迟配置或等定时任务），物品回到在售。
9. admin 违规下架一件物品 → 前台不可见、记录审核留痕。
10. 越权演示：student03 直接访问他人订单详情 / 后台地址 → 403。
11. 缓存演示：同一详情页二次访问命中缓存（日志不再打 SQL）；Redis 中可见 `sc:*` 键。
12. 部署演示：Nginx 反代 + systemd 启动（或展示配置与脚本）。
