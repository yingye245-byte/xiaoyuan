# 项目开发说明与 AI 协作提示词

> 这份文档回答三件事：项目是怎么分层落地的、每个包负责什么、后续要继续加功能应该怎么给 AI 下指令才不会被带偏。
> 如果你是课程结束后回看代码的人，直接读第一章「分层与目录」即可。

## 一、分层与目录

```

├─ src/main/java/com/campus/secondhand
│  ├─ SecondhandApplication.java     启动类（@EnableAsync @EnableScheduling @MapperScan）

│  ├─ config/        Security/MyBatis-Plus/Redis/RabbitMQ/Jackson/AOP/文件 配置
```

### 一次请求怎么走（以「发布物品」为例）

1. `GET /items/publish` → `ItemController#publishPage` 放分类与成色下拉 → `portal/item-publish.html`；
2. 表单提交 `POST /items/publish`（multipart，CSRF token 由 Thymeleaf 自动带上）；
3. `@Valid ItemPublishDTO` 校验标题长度、价格、分类、图片数量；
4. `ItemService#publish`：保存 `tb_item`（状态 0 待审核）→ `saveImages` 落 `tb_item_image` → 发 MQ 站内信 → `upgradeToSeller` 授予卖家角色；
5. 重定向到「我的闲置」，页面顶部 flash 提示「已提交，等待审核」。

## 二、约定（改代码前必读）

| 约定 | 说明 |
| --- | --- |
| 状态常量 | 全部在 `Constants`，且是 **int 原始类型**。比较时必须 `isStatus(Integer, int)` 或 `Integer.valueOf(x) == y`，**不要写 `Constants.X.equals(...)`**（编译不过） |
| 物品状态 | 0 待审核 / 1 在售 / 2 已下架 / 3 已售出 / 4 审核驳回 / 5 交易中 |
| 订单状态 | 0 待支付 / 1 已支付待交付 / 2 已完成 / 3 已取消（含超时关闭，原因写 `cancel_reason`） |
| 缓存 key | 只允许从 `RedisKeys` 取，前缀统一 `sc:`；新增缓存必须同时写「什么时候删」 |
| 模板片段 | 前台 `~{fragments/common :: head(title)/header(active)/flash/pager(page)/empty(text)/itemCard(item)}`；后台 `~{fragments/admin :: head(title)/sidebar(menus, active)/topbar(title)/flash}` |
| 模板陷阱 | `th:replace` 与 `th:if` 不能同标签（replace 优先级更高会吞掉 if），要用 `<th:block th:if>` 包一层；`th:each` 同理 |
| 模型取值 | Controller 传对象用 `${query.keyword}`；**不要**把 `Map` 直接给模板做属性访问（Thymeleaf 的 SpEL 没有 MapAccessor，会 `EL1008E`） |
| 写操作 | 一律 form POST + `th:action`（自动带 CSRF），不用 fetch；只有图表接口是 GET JSON |
| 改资源要重启 | `mvn spring-boot:run` 从 `target/classes` 读模板/静态资源，改 `src/main/resources` 后必须重启 |
| 文件编码 | 所有源文件 UTF-8 无 BOM；**不要用 PowerShell 的 `Set-Content` 批量改源码**，会按 GBK 写坏中文 |

## 三、继续开发时给 AI 的提示词模板

> 直接复制整段（含「禁止清单」）发给 AI，把【】里的内容换成你的需求。

```text
你是本项目的开发者。项目路径 D:\campus-secondhand，Spring Boot 2.7.18 + Thymeleaf + MyBatis-Plus + MySQL8 + Redis + RabbitMQ + Spring Security，JDK 17。

【硬性约束，违反即视为失败】
1. 禁止引入 Vue/React/Element/Axios 等前端框架或 npm 构建，页面必须是 Thymeleaf 服务端渲染。
2. 禁止写 Service 接口再写实现类；直接写 @Service 类。
3. 禁止用 this.setState / alert / confirm / prompt；确认交互用页面内二次点击（data-confirm）。
4. 禁止把 SQL 拼字符串，MyBatis 只能用 #{}；禁止在代码/配置里写真实密码（走环境变量）。
5. 禁止修改 Constants 里状态常量的数值含义；禁止用 Constants.X.equals(...)。
6. 禁止在 th:replace 同标签上写 th:if / th:each；禁止给模板传 Map 后做属性访问。
7. 只改我要求的文件；新增文件必须在回复里列全路径。改完必须给出 `mvn -q compile` 的执行结果。
8. 不要"顺便重构"其他模块，不要改包名、不要动 sql/01-init.sql 的既有数据语义。

【本次任务】
【例如：给物品详情页增加"举报物品"功能，举报记录入 tb_report 表，管理员在后台可查看并下架】

【必须遵守的现有约定】
- 权限：URL 级在 security/SecurityConfig，方法级用 @PreAuthorize，数据级在 service 里校验归属。
- 统一返回：页面请求返回 ModelAndView，Ajax 返回 R.ok/R.fail。
- 缓存：新增读缓存要用 RedisKeys 里的方法，写操作后删对应 key。
- 页面：前台片段引用 fragments/common，后台引用 fragments/admin；样式只加在 app.css/admin.css。
- 数据库变更：新增表/字段要同时改 sql/01-init.sql（幂等写法：CREATE TABLE IF NOT EXISTS / ALTER ... 前先判断）。
```

### 追加需求时的指令示例

- 「给订单列表加分页，每页 10 条」→ 明确要求「OrdersMapper 用 IPage 分页，模板用 `fragments/common :: pager`」；
- 「把首页热门改成按收藏数排序」→ 明确要求「改 ItemMapper 的 order by，并删 sc:item:hot 缓存」；
- 「后台加导出订单 Excel」→ 明确要求「用 EasyExcel 或 Hutool，接口返回文件流，禁止把数据拼成 HTML 表格」；
- 「加一个定时清理过期上传图片的任务」→ 明确要求「写在 task/ 下，cron 可配，删除前先查 tb_item_image 是否仍被引用」。

## 四、常见故障速查

| 现象 | 排查顺序 |
| --- | --- |
| 启动报 `Table 'campus_secondhand.tb_xxx' doesn't exist` | 没导入 `sql/01-init.sql`，或导入了别的库 |
| 启动报 `Access denied for user 'root'` | `MYSQL_PASSWORD` 环境变量与实际密码不一致 |
| 页面 500 且日志 `EL1008E ... HashMap` | 模板对 Map 做了属性访问，改成传 DTO |
| 页面 500 且日志 `NoSuchMethodError ... IWebContext.getExchange` | thymeleaf-extras-springsecurity5 版本必须 3.0.4.RELEASE（不是 3.1.x） |
| 改了页面没生效 | 没重启应用（`target/classes` 是旧资源） |
| 下单后 30 分钟没自动关闭 | RabbitMQ 没启动 / 队列 TTL 参数冲突（改过 `mq.order.delay-ms` 要先删旧队列） |
| 中文乱码 | 检查文件是否 UTF-8、连接串是否 `characterEncoding=utf8`、库是否 utf8mb4 |

## 五、这份代码的取舍（答辩可讲）

1. **不做前后端分离**：课程明确要求 Thymeleaf，且服务端渲染对 SEO 与首屏更友好，也省掉一套构建链。
2. **不做 Service 接口**：单实现类的接口是纯样板，直接类更易读；将来要换实现再抽接口不迟。
3. **订单幂等不用唯一索引**：`(item_id, buyer_id)` 加唯一索引会导致「取消后不能再次下单」，改用 Redis token + 状态 CAS。
4. **图片存本地磁盘**：课程环境没有对象存储，本地磁盘 + Nginx alias 是最稳的方案；若要上云，只需替换 `FileUtils`。
5. **邮件默认 mock**：答辩环境常无外网，mock 模式保证「邮件链路可演示、不报错」。
